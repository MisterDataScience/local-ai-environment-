# Institutions and studio implementation contract

This checklist records the agreed scope. It is not a claim of completion.

- Integrated institution creation in the main Village installer; studio is the first type.
- Independent institution membership, purpose, Library, Archive, workshop and budget.
- Leadership title **Lead Designer**; persistent project ownership and focused local help.
- Preserve both supplied C projects as immutable source snapshots; never discard originals.
- Local folder/ZIP and explicitly selected, commit-pinned GitHub intake.
- Inspect, index, compare and cite code/assets/build instructions; no claim that indexing proves understanding.
- Resumable finite founding analysis prepares knowledge, staff and short navigation maps.
- Final owner approval for staff, access, Library/Archive publication and lasting memories/maps.
- Reproducible build attempts, useful errors, isolated execution, source edits and versioned builds.
- C SDK, portable cartridges and standalone player at **320 × 180**, integer nearest-neighbour scaling.
- Flexible code/working-memory sizes within host limits; obsolete strict retro limits are not reinstated.
- Pausing, deterministic seeded updates, input replay, saved state, screenshots and diagnostic values.
- Accelerated headless tests preserve per-step rules; bounded batches and multiple instances (ten per institution, forty host maximum).
- Local vision inspection on demand, with explicit failure when the installed model cannot inspect images.
- At most four background resident turns; foreground work pauses background sessions, explicit resume only.
- No outsourcing, cloud inference, credential access or arbitrary host commands by studio residents.
- Optional pinned tools installed only when requested; source checks, automatic resource measurements and bounded defaults.
- Encrypted Village backup/restore includes studios; restore never auto-starts jobs. Withdrawal invalidates dependent directions.
- Normal-use owner UI, installation launcher and guide; no manual prompt/map construction expected.
- Three-dimensional rendering and pixel-art authoring are deferred. The runtime interface supports a future player surface.
- No GitHub Actions. Native Mac results must not be represented by Linux fixture results.
