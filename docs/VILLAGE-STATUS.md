# Village implementation status

The single installer combines Village, Commons, layered memories, founding review,
recovery and the installer-hardening work. The five baseline residents are seeded
automatically. The system prepares durable changes; the owner approves them.

## Implemented

- Approved specialist routing and complete Captain proposals for creation,
  revision, retirement and memory maps. No manual agent setup is required.
- Finite Commons gatherings with four active places, owner participation, creative
  formats, private drafts, scoped reads, foreground pause and no outsourcing.
- Layered own memories, deeper-memory glossaries and preferred Library/Archive
  references, with current scope/source checks and separate final approval.
- Resumable local founding review of conversation exports, exact quoted evidence,
  labelled knowledge/preferences/memories and recurring-specialist proposals.
  Approved Library material has a generated Markdown organisation and index.
- Encrypted Village snapshots through the registered workspace, validated recovery,
  preserved previous data and paused restoration of running sessions.
- Reviewed source erasure covering managed originals/overlapping copies, derived
  stores, history, working copies, logs and backup archives. Deletion ledgers prevent
  old-backup restoration and recognised reimport from undoing an erasure decision.
- One consolidated source/package incorporating dependency locks, the selected
  Captain model/adapter, private remote access and service-recovery fixes.

[Founding and recovery](FOUNDING-AND-RECOVERY.md) gives the ordinary owner flow and
precise deletion scope. [Resident memory](RESIDENT-MEMORY.md) and
[Commons](VILLAGE-COMMONS.md) cover everyday use. Manual editing is optional.

## Limits and target-Mac acceptance

Erasure is scoped to managed data, not external downloads, independently retained
provider/backups, or forensic hardware erasure. It conservatively resets derived
knowledge and managed working copies because untracked copied text cannot be
attributed safely. Its displayed plan requires owner approval.

Authoring checks use real storage, HTTP and bridges with simulated models/mounts.
Actual Mac installation, Cryptomator behaviour, native approval UI, model quality,
GPU throughput/memory/cancellation and browser presentation remain unverified here.
Those are target-machine acceptance checks, not missing storage/founding code or
an expectation that the owner builds the agents by hand.

The canonical installer is on main. Updating the repository does not itself
install anything on a Mac. GitHub Actions are not used for this release.
