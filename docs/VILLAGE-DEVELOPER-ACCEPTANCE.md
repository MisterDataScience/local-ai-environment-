# Village developer acceptance

This is a developer checklist for target-Mac validation. It is not a user setup
workflow. Normal use requires no fabricated agents, hand-built memory indexes or
terminal configuration of the Village. The host seeds the baseline residents;
the Captain and host prepare persistent changes for owner approval.

Use disposable synthetic data and the preview installer. Record actual results;
do not represent these checks as passed until performed on the target runtime.

1. Verify native upgrade, FileVault gating and the owner launcher. Opening the
   dashboard must start no inference. Baseline residents must already be present.
2. Use a synthetic recurring task to test Captain preparation of a complete
   specialist proposal. Before owner approval, verify the specialist does not
   exist or receive tasks. Approve the exact proposed active profile, then verify
   ordinary routing selects it for an appropriate task.
3. Approve synthetic memory and Library material. Refresh the dashboard and
   verify the system prepares a map without asking the owner to enter references.
   Pending maps must not enter worker/Commons context. Reject an identical
   suggestion and verify it does not repeatedly return.
4. Approve a prepared map. Inspect a new worker packet and Commons context:
   short directions and selected memory summaries should appear; the full workflow
   should remain absent until the resident follows its reference. Check the real
   model's ability to choose and use this route.
5. Correct/withdraw a synthetic source. Verify stale map entries are withheld and
   a replacement map suggestion is prepared without silently publishing it. Test
   General/private scope isolation and source reclassification.
6. Start a short creative gathering. Verify overlap up to four requests, fair
   rotation and one active coder. Measure responsiveness and memory pressure.
7. Start foreground work, switch modes, stop and restart. Verify paused Commons
   stays paused until explicit resume, cancellation/draining and late-result fencing.
   Closing a host socket alone does not prove immediate GPU cancellation.
8. Test hidden draft/reveal, breakouts, scoped research, distinct final approvals,
   profile revision/retirement, stale proposal refusal, receipts and expiry.

Full encrypted recovery and source-erasure acceptance requires implementing the
remaining storage work first. Track that separately in VILLAGE-STATUS.md. Do not
turn missing engineering into a mandatory owner configuration procedure.
