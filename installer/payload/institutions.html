3. Planning and documentation department
This starts from the studio mission and approved lessons. Four design roles propose different game directions; the Lead Designer selects one. The tree then grows only while consequential design questions remain unresolved. Each answer is reviewed before the next question is opened. There is no fixed depth or leaf-count target, so it will not add branches just to reach 1,000 leaves. A finished dossier contains bounded design decisions for the Lead Designer; it does not contain code tasks or claim the game has been built or play-tested. Saved, bounded turns let the plan pause and resume without one giant context.
This department only plans. It cannot edit project files, build, run machines, publish knowledge, or start implementation. The implementation workbench remains a separate step you start later. Planning uses the local model and your computer's resources.
